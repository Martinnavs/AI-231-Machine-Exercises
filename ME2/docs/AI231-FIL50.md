# ai231 + Filipino persona padding (ai231-fil50): does it close the noise and accent gap?

Status: **rules pre-registered 2026-10-02 20:40, before any run of this experiment had finished; amended before any result: all noise, in training and in evaluation, comes only from the public datasets (ai231 and the fil50 persona set), no ESC-50. Results below (one seed).**
Agent brief: `.scratch/ai231-fil50/agent-prompt.md`. Background and earlier results: `docs/CTC-ATTENTION.md`.

## Question

QuartzNet (stride 2) trained on ai231 alone scores far below the old production model on perturbed audio and on the real
Filipino holdout speaker. Does padding the ai231 v2 train split with Filipino-voiced persona clips, plus the reproducible
dataset-sourced noise and babble pool and the per-variation perturbation table, close that gap?

## Data

`out/conversions/v2/ai231-fil50/manifest.csv` (read-only; builder `src/me2_voicegen/accent_balance/build_ai231_fil50.py` in
the main checkout): all 16,470 rows of ai231 v2 untouched, plus 8,405 `fil50_persona` rows (`group_id` = cloned voice).
Persona voices are split-disjoint (10 train / 2 val / 5 test) and capped per variation (train 50, val 12, test 35); persona
clips are 4,535 of the 14,783 train rows. Test and holdout rows, original or persona, never enter training, threshold choice
or early stopping; val does.

## Recipe (both runs; seed 0)

`vcm.train --manifest <above> --seed 0 --p-rir 0.7 --p-timestretch 0.25 --p-noise 0.5 --p-babble 0.15 --noise-source dataset
--perturbation-plan table --dump-plan --max-minutes 135 --patience 10`; run **P** `--preset quartznet5x3` (plain CTC),
run **H** `--preset quartznet5x3-heads` (CTC + heads, weights 1.0 / 0.3 / 0.1). No ESC-50 in training. The perturbation
table now groups by `label | slot | variation | source_dataset` (see the change note in `docs/CTC-ATTENTION.md`).

## Pre-registered success rules

Noise is never taken from outside the two public datasets (ESC-50 is not used anywhere in this experiment). Measured with the whole-clip CTC path, threshold -0.1, incomplete-prefix margin 4.0, beam 50 (nothing tuned on test).
**Pass = A and B and C and D.** Everything else is reported but does not decide.

- **A. Clean accuracy.** ai231 test, original rows only (`source_dataset=optionb`, `variation_match=exact`, 3,823 in v2):
  intent+slot >= **96.5%**. References on the same rows: old production (`quartznet5x3-s2-fil50-ambient-rir-135m`) 96.9%,
  ai231-only plain baseline 87.3-88.3% (two seeds). Also reported with the margin gate off.
- **B. Perturbed accuracy.** The fixed-seed gate (seed 0: one deterministic reverb plus one noise clip per test clip) with
  the noise taken only from the dataset itself: the test split's own 50 `noise_only` clips (`background_noise` rows).
  Intent+slot >= **90%**. Reference: old production (`quartznet5x3-s2-fil50-ambient-rir-135m`) 93.5% on this gate (the 95.8% in
  the earlier report used an ESC-50 pool and is not comparable).
  The gate adds no babble: some dataset clips already contain background noise or babble, so overlaying more would conflate
  the two. (Training does overlay babble at 15%, as fixed in the recipe above.)
- **C. Transfer to the old internal test.** `optionb-v3-vcmx-fil50` test split: intent+slot >= **93%** on the rows that are
  **not** `fil50_persona` (old production reference to be measured on the same rows; 97.4% on all rows in the earlier
  report). *Adjustment, with reason:* in the old internal manifest all 17 persona voices appear in train, val and test, so
  the 10 voices this experiment trains on are also in that test split's persona rows (a voice-level leak, not clip-level).
  The deciding number therefore excludes persona rows; all-row and persona-only accuracy are also reported and flagged. The 129
  real recordings (`vcm_balanced`) are reported separately (about +-5 points at that size). The deciding rows are therefore the
  1,927 `optionb` + `vcm_balanced` rows (old production scored 97.2% on them in the earlier report). Caveat: the old `optionb`
  rows (1,798) come from the group's own synthetic set, which ai231 also contains, so clip- or voice-level overlap with ai231
  train is possible and not quantified; read C as a transfer indication.
- **D. Rejection.** 0 false accepts on the original ai231 test babble clips (the `optionb` out-of-scope rows, 76), and no
  more false accepts than old production on the 100 test silence/noise rows (`noise_only` 50 + `near_silence` 50; old
  production: 0 of 100, clean). The synthetic negatives (`babble`, `reversed`, `truncated`) are reported per kind, not gated.

Reading rules: persona-only test accuracy (voice-disjoint, 2,946 rows) is a separate table and never mixed into A. **If persona
rows score far above real rows (more than 10 points), or any check fails or looks odd, stop and report.** Holdout (186 real
commands, the Raspberry Pi set) is scored once at the end, reported separately, no tuning. One seed, small subsets: say so.
The classifier path of run H uses the val-fit threshold as before and is reported, not gated.

## Results

**Verdict: the pre-registered success criterion is not met.** Rules A, B and C fail for both new models, and run H also fails
D (one babble false accept in 76). Padding with Filipino persona clips plus dataset-sourced noise helps, but does not reach the
old production model. One seed per run; numbers are intent+slot accuracy on the whole-clip CTC path (threshold -0.1,
margin 4.0, beam 50) unless stated. Full tables: `out/vcm/ai231fil50-compare/report.md` (generated by
`scripts/ai231_fil50_rules.py`).

| model | A clean >= 96.5 | B perturbed >= 90 | C old test, non-persona >= 93 | D babble FA / silence FA | verdict |
|---|---|---|---|---|---|
| **P** plain CTC (`quartznet5x3-ai231fil50-135m`) | 90.2% (3449/3823) FAIL | 76.8% FAIL | 91.6% (1765/1927) FAIL | 0/76, 0/100 PASS | **FAIL** |
| **H** CTC + heads (`quartznet5x3-heads-ai231fil50-135m`) | 91.7% (3504/3823) FAIL | 79.8% FAIL | 92.4% (1780/1927) FAIL | 1/76, 0/100 FAIL | **FAIL** |
| old production (reference) | 96.9% | 93.5% | 97.2% | 0/76, 2/100 | PASS |
| ai231-only plain baseline, seed 1 (reference) | 87.3% | 73.2% | 89.3% | 1/76, 0/100 | FAIL |
| ai231-only heads-A, seed 1 (reference) | 87.5% | 76.1% | 88.8% | 0/76, 0/100 | FAIL |

Training: P stopped by early stopping at epoch 38 (best val loss 0.5140), H at epoch 44 (0.5386); no non-finite losses; CTC-infeasible
samples at stride 2: 0 in train (all epochs) and 0 in val. Head labels covered all 614 slot-value paraphrase rows.

**What improved against the ai231-only baselines (seed 1):** clean +2.9 (P) / +4.2 (H) points over the plain baseline / heads-A;
perturbed +3.6 / +3.7; old-test non-persona rows +2.3 / +3.6; persona-only test (5 unseen voices) 95.1% / 95.9% against 79.0% / 78.7%.
The persona-only gain is voice-disjoint generalisation to unseen cloned Filipino voices, and also the easiest subset. Persona
rows score 4-5 points above the original rows, below the 10-point alarm in the rules.

**What did not close:**
- *Perturbed audio:* 76.8% / 79.8% against 93.5% for old production on the same dataset-noise gate. The noise pool is only 174
  `noise_only` clips plus synthetic coloured noise; the old production model trained on a much larger and more varied ambient set.
- *Real recordings in the old internal test* (129 `vcm_balanced` clips; roughly +-7 points at this size): P 78.3%, H 76.0%, which is
  **lower** than the ai231-only baselines (86.0% / 88.4%) and far below old production (96.9%). Padding with persona clips (a third of
  train) may have shifted the models toward synthetic voices; not investigated. Read with the small sample in mind.
- *Margin gate:* with the gate off, A is 92.5% (P) and 92.7% (H), so the margin 4.0 gate costs 2.3 and 1.0 points (old production: 0.2).
- *Rejection:* P rejects the 100 test silence/noise rows and 76 original babble clips completely; H lets one babble clip through.
  By synthetic-negative kind (CTC, 50 clips each): `babble` P 0, H 1; `reversed` 0 and 0; `truncated` P 1, H 2. (Old production accepts 3 / 1 / 9.)
  The pre-registered "old production 0 of 100" for silence was wrong (measured 2 of 100); the verdicts are the same under either reading.
- *Holdout* (186 real commands, scored once, not tuned on): P 60.2%, H 65.6% (classifier at the val-fit threshold 61.8%), against
  54.8% / 53.8% for the ai231-only baselines, 52.2% for heads-A and 83.9% for old production. On the 84 clips of the one
  real Filipino speaker: P 16.7% (14/84), H 28.6% (24/84); the ai231-only CTC models were 6-17%. Synthetic and other holdout voices: 96.1% (98/102) for both.

**Classifier path (run H).** Threshold 0.9831, the smallest meeting the val CTC false-accept rate of 0.8%: clean 90.4%, perturbed
79.6%, persona-only 94.4%, old test non-persona 89.8%, babble false accepts 2/76. That threshold is strict. Plain argmax (no
rejection) gets 98.1% clean but accepts 29 of 76 babble clips; on the holdout Filipino speaker argmax gets 58.3% (49/84).
The classifier is still more accurate than the CTC path, and the rejection side is what costs it, as before.

**Caveats.** One seed per run; 129 real recordings and 84 single-speaker holdout clips are small. Both runs early-stopped at epoch
38-44 under a OneCycle schedule sized for 150 epochs, so the learning rate had not annealed (same as the earlier runs): the numbers
likely understate what these recipes can reach, and the gap to old production cannot be attributed to data alone. The old internal
test shares source material with ai231 (its `optionb` rows), so C is a transfer indication, not an independent test.

**What I would do next (not done):** (1) rerun P and H with `--onecycle-epochs` matched to the expected length (about 50) and a second seed,
to separate under-annealing from data; (2) widen the noise pool within the public datasets or lower the persona share, to see whether
the real-recording drop and the perturbed gap move; (3) ticket 04 (classifier as a pre-selector for the beam search), judged on streaming
replay, since the classifier's accuracy is far above the CTC path's.

## Round 2: schedule fix, supplemental data, no stacked noise (pre-registered 2026-10-02 22:03, before training)

Two runs of the H recipe (`quartznet5x3-heads`, seed 0), both with the learning-rate schedule matched to the expected length
(`--onecycle-epochs 60 --max-epochs 70 --patience 20`, so the rate anneals instead of stopping near its peak):

- **H-sched** (`quartznet5x3-heads-ai231fil50-sched`): the round-1 H data and recipe; only the schedule changes.
- **H-all** (`quartznet5x3-heads-ai231fil50supp-sched`): the same schedule, plus (1) the ai231 `supplemental_synth` clips of train
  voices (3,517 train + 466 val; its 1,873 test- and holdout-voice clips are excluded; none is byte-identical to any ai231 clip;
  manifest `out/conversions/v2/ai231-fil50-supp/`, `scripts/build_ai231_fil50_supp.py`), (2) `--skip-prenoised`: no added noise
  or babble on the 7,253 train clips that are already noisy (`*_noisy.wav`), which still get reverb and stretch, and (3)
  `--noise-random-offset`: each noise / babble mix starts at a seeded random point in the clip instead of its first seconds.

Same rules A-D, same evaluation, same reading rules as above; H-sched vs round-1 H shows the schedule's effect, H-all vs H-sched
the effect of the three data/noise changes together (they are not separated). H-all's val split has 466 extra clips, which only
affects early stopping and the classifier-threshold fit is still on the original ai231 val rows. One seed each.

## Results: rounds 2 and 3 (scored 2026-10-03; one seed each)

Tables: `out/vcm/ai231fil50-compare/report-round3-full.md` and `report-round3-nonoverlap.md` (`scripts/ai231_fil50_rules.py`).

### A leak in the evaluation that changes how every number here reads

2,632 of the 4,895 ai231 test and holdout rows are **byte-identical to clips in the internal training data**, and 2,885 of the 3,823
test originals (75%) come from speakers that also appear in the internal training split. Old production and the `fil50-*` models trained on
that data, so their ai231 test numbers are inflated: old production drops from **96.9% to 92.0%** clean and from 93.5% to 87.9% perturbed on
the 1,261 rows that are not byte-identical, and to **89.6%** on the 393 rows that are neither identical nor from a speaker in the internal
train split. The pass bars of rules A and B (96.5% and 90%) were set from old production's inflated figures before this was known; old
production itself would fail them on the non-overlapping rows. The pre-registered verdicts below are kept as registered. The internal-data
model **H-int** was trained on the internal manifest with every clip identical to any ai231 test or holdout clip removed (and the noisy copies
mixed from them), but near-duplicates and shared speakers remain, so its full-set numbers are still inflated; compare on the subsets.

H-wide, trained only on public data, matches old production and H-int on rows they could not have memorised (within a few points; the
small subsets are about +-3 to 7 points). The sections of the picture that stay open:
- *Real Filipino speaker (84 clips, never in the internal data):* H-int **69.0%** CTC (66.7% classifier, 78.6% argmax), H-wide 31.0% (33.3%, 52.4%),
  H-all 19.0% (34.5%, 60.7%), H-sched 19.0%. The 69% matches old production's 67.9%. So the accent gap is closed by the internal data, not by
  anything done to the public data so far: the internal manifest holds 11,509 persona train clips plus 7,547 noisy copies, against 4,535
  persona clips capped per variation here.
- *Holdout, all 186 commands (non-overlapping 122):* H-int 84.9% (77.0%), H-wide 66.7% (50.8%), H-all 60.8% (42.6%), H-sched 58.1% (41.0%).
- *Rejection (CTC false accepts, 50 clips each):* the internal-data model is looser: `truncated` H-int 11/50 (old production 9/50) against
  H-wide 2/50 and H-all 3/50; `babble` H-int 3, H-wide 1.

### What each change did (one seed each, so differences of about 3 points are not reliable)

- **Schedule fix alone (H-sched vs round 1 H):** no help, clean 88.0% vs 91.7%, perturbed 71.9% vs 79.8%. Best val loss was at epoch 23 and
  the run early-stopped at 43 either way, so under-annealing is not what holds these models back.
- **Supplemental clips + no stacked noise + random noise offsets (H-all vs H-sched):** clean +4.4, perturbed +5.6, real recordings of the old
  test 77.5% to 93.0% (n=129). The three changes were not separated.
- **Width, 4.18 M parameters (H-wide vs H-all):** clean +2.6, perturbed +10.3 (87.8%), persona-only 98.7%, real recordings 96.1%. Training
  loss reached 0.158 against val 0.50 (it early-stopped at epoch 58, best epoch 38), so it fits the training data far more tightly.
- **Classifier path:** plain argmax is 98.0-99.2% clean for every heads run. At the val-fit threshold H-wide gets 97.5% clean and 92.4%
  perturbed but accepts 3/76 original babble clips and 21/76 at argmax; H-int 97.8% / 92.6% with 1/76. Its babble acceptance at the threshold is
  the cost, as before.
- **Size:** H-wide is 4.18 M parameters, ~4.2 MB estimated INT8 (not yet exported or measured on the Pi).

### What this says

1. The 96.5% and 90% targets are not reachable by comparison with a number that was inflated by overlap; on rows production has not seen, H-wide
   (public data only) is already level with it on clean and perturbed audio.
2. The remaining distance to production is the real Filipino speaker (31% against 69%) and rejection behaviour in the opposite direction
   (ai231-trained models reject truncated commands better). Both trace to the training data, not to the architecture or schedule.
3. Next, in order: (a) add the internal-style Filipino material that the public set lacks (the full 14,393 persona clips and noisy copies, not
   the capped 4,535) to the H-wide recipe; (b) a second seed of H-wide and H-int before trusting the 2-3 point gaps; (c) export H-wide to INT8
   ONNX and measure size and latency; (d) ticket 04 (classifier as pre-selector), judged on streaming replay.

## Internal held-out set (no training source has seen it)

Built by `scripts/build_internal_heldout.py` from the **internal test split**, into `out/conversions/v2/internal-heldout/` (manifest only;
paths point back at the source audio). A clip is kept only if (1) it is an `optionb` / `vcm_balanced` command or a `filipino_speech_corpus`
speech clip (rejection probe), never persona, ambient copies or ESC-50; (2) its audio is not byte-identical to any ai231 clip or any internal
train/val clip; (3) its speaker is absent from internal train/val and from ai231 train/val (a speaker that is only an ai231 test or holdout
speaker is accepted, because no model trains on it). So it is unseen by old production, by H-int and by every ai231-trained model. Noise for
the perturbed pass is the ai231 test `noise_only` clips (public data only). Near-duplicates are not detectable.

Why not speaker-disjoint from ai231 as a whole: the internal data and ai231 share their voice pool (all 10 internal-test synthetic voices and
15 of 17 internal-test real speakers also appear in ai231), so almost nothing labelled is disjoint from ai231 at the speaker level; only voices
that ai231 itself keeps for test or holdout can be used. Of 2,170 candidate internal test clips, 782 + 24 are identical to ai231 clips and
659 come from speakers in ai231 train/val; 705 remain.

Composition: 562 synthetic command clips from 5 voices, 76 real command clips from 4 speakers (Fluent Speech Commands 18, Multi-Sensor 58),
all 19 intents (9 to 90 clips each, median 30), plus 32 Filipino speech clips and 35 other speech clips as rejection probes. **It is not a
Filipino-accent test**: the persona voices cannot be held out (all 17 are in every training set) and no real Filipino speaker is eligible.

sapinsapin persona voices, 648 of them QA-passed). Evaluation manifests: `scripts/build_user_voice_eval.py` writes

## Inference cost: tiny (1 MB) vs wide (4 MB)

Measured 2026-10-03 on the training server (ONNX Runtime, INT8, one 2.5 s window, 126 output frames, medians of 60 runs; the Raspberry Pi
was not measured). H-wide exported with `vcm.export_onnx`: INT8 4,156,784 B, fp32 16.2 MB.

| | tiny (`quartznet5x3-heads`) | wide (`quartznet5x3-wide-heads`) |
|---|---|---|
| feature extraction + network forward, 1 thread | 4.3 ms | 14.6 ms |
| same, 4 threads | 3.3 ms | 7.4 ms |
| grammar beam search (beam 50) | ~90 ms | ~90 ms (does not depend on the network) |

The wide network costs about 10 ms more per window; the beam search is nearly all of the per-window latency for either model, so
~95 ms vs ~105 ms in total, which a listener would not notice. The streaming stride is 250 ms: on the Pi the pure-Python beam search is
the likelier real-time risk, which is what ticket 04 (classifier-guided decode) would cut. The 1,048,576 B INT8 cap in that ticket is a
repo convention for the heads export, not a latency requirement, and can be relaxed for the wide model.

### Serving mode and ticket 04 re-evaluation (2026-10-03)

**Serving.** Decision: load both models together (wide for CTC, xl for the heads), policy A. `HybridDecoder` in `vcm/hybrid.py` keeps both resident and,
per clip, returns a trace (CTC intent/confidence, classifier intent/confidence, agreement, which path answered) and counts `answered_by_ctc/cls/none`,
and, when the truth is supplied, `ctc_right`, `cls_right`, `both`, `only_ctc`, `only_cls`, `neither`. `LazyCascade` stays available for memory-tight use.

**Which component is right (wide CTC vs xl classifier, intent+slot, targets):**

| set | both | only CTC | only classifier | neither | CTC rejected (classifier recovers) | CTC answered wrongly (classifier right) |
|---|---|---|---|---|---|---|
| ai231 test clean (3,823) | 3591 | 42 | 145 | 45 | 187 (145) | 3 (0) |
| ai231 test perturbed | 3273 | 82 | 279 | 189 | 455 (274) | 13 (5) |
| holdout (186) | 120 | 4 | 23 | 39 | 59 (20) | 3 (3) |
| 129 real recordings | 106 | 18 | 3 | 2 | 5 (3) | 0 (0) |

CTC almost never answers wrongly; its errors are rejections, which the classifier fallback recovers. The classifier is worse on the 129 real
recordings (18 only-CTC), the reason both are kept. On the holdout 39 of 186 are wrong for both: that is acoustic coverage of the accent, not decoding.

**Ticket 04 (classifier as pre-selector for the beam search).** It is a speed ticket (its stated gain is the beam search time; CTC keeps deciding
acceptance and slots), so it cannot move accuracy or the rejection errors above. Re-evaluated against the new findings: (1) the classifier already runs in
the serving path, so its cost is paid; (2) beam search is the larger share of a window (wide, fp32, one core: encoder 19 ms, beam 41 ms, 68%), so the
premise still holds; (3) top-k recall of the xl intent head: k=1/2/3/5 = 99.3/99.6/99.8/99.9% (ai231 clean), 96.9/98.4/99.1/99.5% (perturbed),
84.9/93.0/93.5/96.2% (holdout, real accent), 94.6/96.9/99.2/100% (129 real); restricting the grammar would therefore remove the true intent from the search
on about 6.5% of holdout clips at k=3, which the pre-registered "correct first trigger within 1 pp" would catch; (4) the Pi's per-window time is unmeasured, so
whether 41 ms of beam search matters on the target is unknown. Recommendation: defer; it is not needed for accuracy and its speed value depends on a Pi
latency measurement. Revisit only if that measurement shows the window time above the stride, and then start with K=3 and the xl head as pre-selector.

## Hybrid in streaming (wake word + endpointed), 2026-10-03

`EndpointedPeriodPolicy` takes an optional classifier fallback (`vcm/streaming/policy.py`). The CTC path is unchanged: it fires on the first
window that is confident, stable for `--stable-strides` decodes and ended (`--hold-ms` of trailing blank). When a window is not accepted by the CTC,
the speech has ended for the longer `--cls-hold-ms` (default 500 ms) and the window holds at least `--cls-min-speech-ms` (default 200 ms) of non-blank
frames, the heads model (`--cls-model`, ONNX or checkpoint) classifies the window once; above `--cls-threshold` (default 0.8787) its intent and slot fire,
with `"text": "[classifier]"` and `policy_reason` naming the fallback. Off unless `--cls-model` is given. The two fallback defaults are reasoned, not tuned.

```bash
# live microphone: wake word, then the command; answers when the command ends
uv run python -m me2_voicegen.vcm.streaming \
  --model out/vcm/hybrid-ctcwide-clsxl/ctc-wide --backend onnx --onnx-variant int8 \
  --grammar optionb --threshold=-0.1 --required-command-margin 4.0 --beam-width 50 \
  --gate wakeword --policy endpointed --gate-period 3 --hold-ms 200 --stable-strides 1 \
  --wakeword-model out/wakeword-sesame-ambient-rir-45m --wakeword-backend onnx --log-periods \
  --cls-model out/vcm/hybrid-ctcwide-clsxl/cls-xl/export/vcm_heads.int8.onnx --cls-threshold 0.8787 \
  --source mic                      # or --source path/to/session.wav for file replay

# replay evaluation on wake word + command sessions (drop --cls-* for the CTC-only baseline)
uv run python -m me2_voicegen.vcm.streaming.session_replay --split test \
  --vcm-manifest out/conversions/v2/ai231-v2/manifest.eval-exact.csv --out-dir <sessions dir>
uv run python -m me2_voicegen.vcm.streaming.replay_eval --sessions <sessions dir> --model out/vcm/hybrid-ctcwide-clsxl/ctc-wide \
  --threshold -0.1 --margin 4.0 --policy endpointed --period-s 3 --hold-ms 200 --stable-strides 1 \
  --cls-model out/vcm/hybrid-ctcwide-clsxl/cls-xl/export/vcm_heads.int8.onnx --cls-threshold 0.8787 --out <report.json>
```

**Replay results** (784 sessions from the ai231 test split: room tone = the dataset's own noise clips, a real wake-word clip, then the command;
all PAUSE/STOP/TIME clips plus the first 30 of each other intent; both INT8 ONNX; summaries in `out/vcm/hybrid-ctcwide-clsxl/eval/streaming-replay-*.json`):

| | correct first trigger | missed | wrong-intent triggers | early first triggers | latency after speech end p50 / p95 |
|---|---|---|---|---|---|
| wide CTC only | 692 (88.3%) | 83 | 9 | 19 | 0.38 / 0.59 s |
| hybrid | 701 (89.4%) | 73 | 10 | 24 | 0.38 / 0.60 s |

The hybrid is right on 10 sessions the CTC misses and wrong on 1 it got right. 47 of the hybrid's 73 misses never opened a period (the wake word did not
fire), so they are a wake-word limit, not a decoding one; on the 737 sessions where the period opened, 95.1% vs 93.9% correct. The streaming gain is much
smaller than the whole-clip gain (98.8% vs 95.0%) because in streaming the CTC sees several growing windows and already accepts more commands, and the
fallback only fires after its longer hold. Early first triggers rise from 19 to 24 (5 of the 24 hybrid early triggers are wrong). One seed, one session build;
not run on a live microphone or a Pi. Fallback hold and minimum speech are untuned; tune on a val session build only.
